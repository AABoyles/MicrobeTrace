# AGENTS.md

MicrobeTrace is a browser app for visualizing molecular epidemiology data: networks, trees, maps
and charts built from sequences, link lists, distance matrices and node tables. It runs entirely
client-side; `server.js` only serves static files. Node >= 26.

## Commands

```sh
npm ci
npm test                                      # unit tests (node --test test/unit/*.test.js and *.test.mjs)
npm run test:e2e                              # Playwright, Chromium only; starts its own server
npm run test:e2e -- test/e2e/histogram.spec.js   # one spec
npm run typecheck                             # tsc over the files that start with // @ts-check
npm run lint                                  # ESLint; errors fail CI, and the warning count should stay at 0
npm start                                     # http://localhost:5000 (builds dist/ first if missing)
npm run bundle && npm run cache               # build dist/, vendor/, fonts/ and sw.js (not committed)
```

E2E needs `npx playwright install chromium` once (or set `PLAYWRIGHT_CHROMIUM_EXECUTABLE`). It runs
serially and is slow; run the specs for what you touched, not the whole suite, unless asked.

## Layout

- `index.html` - the page: menus, global dialogs, and the `<script>` tags, in load order.
- `src/` - app code. `mt.js` makes the page's `MT` with `createMT` from `common.js` (the core,
  `MT.*`). `index.js` wires the page, `settings.js` is the settings store, `events.js` the event
  bus, `session.js` the owner of `session.data`, `graph.js` the network store, `nodes.js` per-file
  node values and provenance, and `formats/` the file formats, one module each.
- `components/` - one view per `NAME.html` + `NAME.js` pair; the `.js` is an ES module that
  `views.js` loads with `import()`. See `components/AGENTS.md`.
- `workers/` - Web Workers for parsing and heavy computation. See `workers/AGENTS.md`.
- `src/webmcp.js` (the core) and `src/webmcp/` (one file per tool) - tools for AI agents. Read
  `src/webmcp/README.md` before touching them.
- `dist/`, `vendor/`, `fonts/` - built third-party code, **not committed** (gitignored, except
  `vendor/bx_distance_models*` and READMEs). Generated by `scripts/bundle.js` from `node_modules`;
  never edit by hand (see `vendor/README.md`). `sw.js` is generated too, from `scripts/sw.template.js`.
  A fresh clone needs `npm ci`; `npm start`, `npm test` and E2E build the rest when it is missing.
- `test/unit`, `test/e2e`, `test/golden`, `test/security` - each has a README worth reading first.

## How the code is written

- No build step for app code, and no bundler for the app's own modules. Most app code is an ES
  module that `import`s what it uses. The leaf files (`events`, `settings`, `graph`, `nodes`, `dates`,
  `db`, `session`, `session-format`, `binder`, `aligner`, `formats/`) are modules (#323, #337, #338):
  they `export` their API and, until their users convert too, also set it on `globalThis`. New code
  that other files depend on should be a module with `import`s, not a global.
  The core scripts split from `common.js` (`common`, `loading`, `links-clusters`, `colors`, `export`,
  `views`, `ui`) are modules too, and importing one does nothing (#341): `createMT(env)` in `common.js`
  makes an `MT`, runs the others' `installX(MT, env)` on it and returns it. `src/mt.js` calls it once
  and sets `self.MT`. `env` is `self` on the page; it supplies `session`, `temp` and `layout`, which the
  installed functions read as `env.session` and so on, while `document`, `Worker` and the libraries are
  read as globals. They still call each other through `MT.x` at run time. Unit tests that need a fresh
  `MT` per test call `createMT` with a fake `env` and set the globals they fake on `globalThis` (see
  `test/golden/harness.js`).
  Still classic scripts: `src/theme.js` and `src/https.js` (in the head), `src/index.js`, `src/webmcp.js`
  and the workers. They read `MT`, `session` and `temp` as globals. Views (`components/`) and the WebMCP
  tools (`src/webmcp/`) are modules (#339, #340), and a view takes `MT`, `session` and `temp` from its
  `ctx` (see `components/AGENTS.md`).
  Module scripts are deferred: they run in document order with the `defer` scripts, after the
  synchronous ones (such as `dist/bundle.primary.js`). So a synchronous script can't use `MT` or the
  leaf modules, and a `defer` script can use only the modules placed before it in `index.html`.
  Workers can't `importScripts` a module, so a file a worker loads stays classic. Libraries come from
  the bundles as globals (`d3`, `bootstrap`, `Plotly`, ...); the large ones load on first use through
  `MT.loadLibrary` (#324).
- State: `session` is what gets saved (data in `session.data`, settings in `session.style.widgets`);
  `temp` is everything rebuilt on load. Read and write settings through `MT.settings.get/set` so
  subscribers hear about it; new settings need a default in `MT.defaultWidgets` in `common.js`.
  Write `session.data` through `MT.session` (`src/session.js`: `addNode(s)`, `addLink(s)`,
  `addNodeField`, `addLinkField`, `excludeNodes`, `setReference`, `setClusters`, `reset`, ...), which
  emits `session-data-change`; a lint rule (`noDirectData`) rejects direct writes. Add a function there
  when you need a new kind of write. Node flags (`selected`, `visible`, ...) are still set in place.
- The CSP (in both `index.html` and `server.js`) forbids inline scripts, `eval`, and fetching from
  other origins. Don't add inline handlers, `new Function`, CDN links, or `blob:` images.
- Treat every loaded value (IDs, field names, values, session files) as hostile. Values are stored
  as loaded and escaped where shown: use `textContent`, or build elements, never interpolate data
  into `innerHTML`. `test/e2e/injection.spec.js` checks this with the files in `test/security/`.
- Genetic distances can be `NaN` (no comparable sites) or `Infinity` (saturated), and corrected
  distances can exceed 1. Code that consumes distances must tolerate both.
- Comments explain why, in plain sentences, and cite the issue (`(#253)`). Keep that style.
- UI text is plain English and is tested (`words.spec.js`, `menus.spec.js`, `a11y.spec.js`): every
  control needs an accessible name and every input a visible label. Dialogs follow the two kinds in
  `CONTRIBUTING.md` (live settings dialogs vs. modal action dialogs).
- 2-space indent, LF, final newline (`.editorconfig`). Match the surrounding file otherwise.

## Before you finish

- `dist/`, `vendor/`, `fonts/` and `sw.js` are built, never committed (#325); CI, the Docker build and
  the Pages deploy run `npm run bundle && npm run cache` themselves. Changed `package-lock.json` or
  `scripts/bundle.js`? Run `npm run bundle && npm run cache` yourself to try it. A runtime file outside
  `src`, `components`, `workers`, `vendor`, `dist`, `fonts` and `img` needs adding to `EXTRA_FILES` in
  `scripts/build-site.js`, or the server returns 404 for it. The service worker's own code is in
  `scripts/sw.template.js`, not `sw.js`.
- Patching a dependency means a `scripts/patch-*.js` applied by `bundle.js`, not an edit to `dist/`.
- CI runs `npm run lint` and `npm run typecheck`. `no-unused-vars` and `eqeqeq` are errors, so
  keep the warning count at zero; loose equality needs a disable comment that says why (#346).
- Behaviour changes need tests: unit tests for logic that runs in Node, an E2E spec for UI.
  Add a row to `test/e2e/README.md` for a new spec.
- Known numerical discrepancies in the golden tests are `todo` tests, and known console errors live
  in `KNOWN_ERRORS` in `test/e2e/helpers.js`. Remove the entry when you fix the bug; don't add
  entries to make a test pass.

## Commits and PRs

Subject lines say what changed in user-facing terms, in the imperative, with the issue:
`Draw big scatterplots on a canvas ... (Fixes #252)` or `(Refs #301)`. Explain the why in the body.
PRs go to `master`.
